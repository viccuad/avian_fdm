# Migrating From v0.2 to v0.3

## FDM precision: `Scalar` and `Vector` replaced by `f32` and `Vec3`

Avian 0.8 stores velocities, rotations, forces, torques, and mass properties in `f32` in both
precision modes. Only world positions (`Position`) stay in `f64` when the `f64` feature is on.
An FDM that calculates in `f64` must convert every result to `f32` when it writes the result to
Avian, so the extra precision has no effect. For this reason, all FDM math and all public data
types of `avian_fdm` now use `f32`, `Vec3`, and `Quat` in both precision modes.

In `f32` builds, the types are the same as before. In `f64` builds, these items change from
`avian3d::math::Scalar` (`f64`) to `f32`:

- `AeroCoeff`: the value of `AeroCoeff::Scalar`, and the vectors of `Table1D` and `Table2D`.
- `AeroCoeff::evaluate`, `AeroCoeff::with_post_stall_lift`, `AeroCoeff::with_post_stall_drag`.
- `AirfoilData::with_post_stall`.
- `airfoil::foil_tools::parse_foil_tools_csv`: the tables in the returned `FoilToolsPolars`.
- The ISA functions `isa_temperature`, `isa_pressure`, `speed_of_sound`, `sutherland_viscosity`,
  and `atmosphere_at`: arguments and return values.
- `AtmosphereState`: all fields.
- `WindResource::velocity_world_ms`: now `Vec3` instead of `avian3d::math::Vector`.
- The fields of the components `FlightState`, `ControlInputs`, `AircraftGeometry`,
  `LodDamping`, `InducedDrag`, `Failure`, `AeroZone`, and `EngineZone`.
  `EngineZone::thrust_axis_body` is now `Vec3`.
- `get_remaining`: the return value.
- `damping_torque` and `zone_local_angles`: arguments and return values. `damping_torque` takes
  a `Quat` and returns a `Vec3`.

To migrate, replace `avian3d::math::Scalar` with `f32`, and `avian3d::math::Vector` with `Vec3`,
in the code that builds or reads these types:

```rust
// 0.2, with the `f64` feature
use avian3d::math::Scalar;
const ALPHA_BP: [Scalar; 3] = [-0.2, 0.0, 0.2];

// now
const ALPHA_BP: [f32; 3] = [-0.2, 0.0, 0.2];
```

```rust
// 0.2, with the `f64` feature
fn ramp_throttle(mut query: Query<&mut ControlInputs>, time: Res<Time>) {
    let throttle = (0.5 + time.elapsed_secs_f64() / 50.0).min(0.75) as Scalar;
    for mut ctrl in &mut query {
        ctrl.throttle = throttle;
    }
}

// now
fn ramp_throttle(mut query: Query<&mut ControlInputs>, time: Res<Time>) {
    let throttle = (0.5 + time.elapsed_secs_f64() / 50.0).min(0.75) as f32;
    for mut ctrl in &mut query {
        ctrl.throttle = throttle;
    }
}
```

Avian 0.8 also uses `f32` for its components, except `Position`. See the next section.

## Bevy 0.20 and Avian 0.8

`avian_fdm` now requires Bevy 0.20 and Avian 0.8. Avian 0.7 depends on Bevy 0.19, so the two
upgrades happen together. Read the upstream guides for the changes in your own code:

- [Bevy 0.19 to 0.20](https://bevy.org/learn/migration-guides/0-19-to-0-20/)
- [Avian 0.7 to 0.8](https://github.com/avianphysics/avian/blob/main/migration-guides/0.7-to-0.8.md)

The Avian changes that affect code that uses `avian_fdm`:

- Avian 0.8 removes `avian3d::math::Scalar`, `Vector`, and `Quaternion`. `Rotation`,
  `LinearVelocity`, `AngularVelocity`, `ConstantForce`, `ConstantTorque`, `ColliderDensity`,
  `Mass`, and the `Collider` constructors use `f32`, `Vec3`, and `Quat` in both precision modes.
  Only `Position` uses the active precision (`avian3d::math::Real` and `RVector`).
- Avian 0.8 removes the `avian3d/f32` feature. Single precision is the default when `f64` is
  off. If your own `avian3d` dependency enables `f32`, remove it.

```rust
// 0.2, with Avian 0.7
use avian3d::math::Vector;
commands.entity(root).insert(LinearVelocity(Vector::new(27.0, 0.0, 0.0)));

// now
commands.entity(root).insert(LinearVelocity(Vec3::new(27.0, 0.0, 0.0)));
```

## Cargo features: `f32` replaced by `parry-f32` and `parry-f64`

The `avian_fdm` features now mirror the precision features of Avian 0.8. Avian 0.8 removes its
`f32` feature: single precision is the default when `f64` is off, and `parry-f32` or `parry-f64`
selects the collider backend. With one name for each switch in both crates, the features of
`avian_fdm` and `avian3d` cannot disagree.

- The `f32` feature is removed. Use `parry-f32`. It is a default feature.
- `f64` now changes only the precision of world positions. The FDM still calculates in `f32`.
- `parry-f64` enables `f64` and the f64 collider backend.
- Enable exactly one of `parry-f32` and `parry-f64`. If you enable none, the build fails with a
  message that names both.

The same features exist in `avian_fdm_j3cub_jsbsim`.

```toml
# 0.2
avian_fdm = { default-features = false, features = ["f64", "debug-plugin"] }

# now
avian_fdm = { default-features = false, features = ["parry-f64", "debug-plugin"] }
```

## CCD defaults: aircraft pass through each other

Avian 0.8 replaces its unbounded speculative collision with swept CCD. By default, Avian sweeps
a fast body only against static and kinematic bodies. Aircraft are dynamic bodies, so two
aircraft that fly into each other pass through each other. At a closing speed of 80 m/s and a
60 Hz physics step, each step moves 1.3 m, which is much more than the thickness of a wing.

`avian_fdm_j3cub_jsbsim::presets::j3cub::j3cub_core_bundle` now includes `SweptCcd` with
`CcdFilter::DYNAMIC`. For your own aircraft, add the same component to the root entity:

```rust
commands.spawn((
    AircraftCoreBundle { /* ... */ ..default() },
    SweptCcd::default().with_filter(CcdFilter::DEFAULT | CcdFilter::DYNAMIC),
));
```

Limits of swept CCD:

- Two fast aircraft on crossing paths can still miss each other, because each sweep tests the
  start position of the other body. Add `SpeculativeCcd` for this case. It can give small
  impulses to aircraft that fly close together, for example in formation flight.
- At the time of impact, Avian moves the fast body back. The body stops for that step.
- For bullets and missiles, do not use rigid-body contacts. Use a hit-scan with the relative
  motion of the two bodies, for example `avian3d::collision::collider::contact_query::time_of_impact`.

Refer to the "Numeric Precision" section of the crate documentation.
